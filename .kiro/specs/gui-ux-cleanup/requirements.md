# GUI UI/UX 정리 — Requirements

데스크톱 GUI(`stardustlib/gui/`)를 dev-config.json으로 실제 실행해 화면과 위젯
지오메트리를 확인한 결과, 스토리지 관리 버튼이 화면에 드러나지 않는 결함 한 건을
확인했다. 그 밖에 다이얼로그 연쇄, 상태 표기, 키보드 접근 등 사용 흐름상의 문제를
함께 정리한다.

## 관측 기록 (2026-07-30)

실행: `StardustApp(root, "dev-config.json")`, 다크 테마, 언어 ko, 기본 창 900x620.

스토리지·디바이스 패널 하단의 액션 바(`루프백 추가`, `제거`)가 화면에 없다. 위젯
지오메트리 덤프에서 그 프레임의 높이가 900x620·760x480 모두 `h=1`이었다.
`_build_mgmt_panel`이 트리 컨테이너를 `expand=True`로 먼저 pack하고 액션 바를 나중에
pack하기 때문에, 패널에 배정된 높이를 트리가 전부 가져간다. 스토리지 추가·분리는 이
버튼 외에 다른 진입점이 없어 기능에 도달할 수 없다.

원인 구조는 146f005(2026-07-26)가 메인 창 본문에서 고친 것과 같다. 그 수정은 `body`
수준의 배치 순서만 바로잡았고, 관리 패널이 하단으로 들어온 7a0dfc3(2026-07-06) 이후
패널 내부에는 같은 실수가 남아 있다. 상태바·액션 툴바는 146f005 이후 정상이며 이번
관측에서도 기본 창에서 모두 보였다.

## Requirement 1: 하단 영역이 올바른 순서로, 잘리지 않고 보인다

사용자 스토리: 사용자로서, 파일 목록에 대한 액션 버튼이 그 목록 바로 아래에 있기를
바라고, 창을 최소 크기로 줄여도 스토리지 추가·분리 버튼이 사라지지 않기를 바란다.

### Acceptance Criteria

1. THE 메인 창 SHALL 세로 배치를 다음 순서로 구성한다: 경로 바 → 파일 목록 →
   파일 액션 툴바 → 스토리지·디바이스 패널 → 상태바.
2. THE 파일 액션 툴바 SHALL 파일 목록과 같은 영역에 묶여, 분할선을 드래그해도 파일
   목록 바로 아래에 붙어 있다.
3. WHEN 창 크기가 최소 크기(760x480) 이상이면 THE 스토리지·디바이스 패널 SHALL
   액션 바를 높이 24px 이상으로 표시한다.
4. WHEN 세로 공간이 부족하면 THE 레이아웃 SHALL 파일 목록과 관리 트리의 높이를 먼저
   줄이고, 파일 액션 툴바·관리 액션 바·상태바는 마지막까지 유지한다.
5. WHEN 사용자가 분할선을 위로 끌어 파일 목록 영역이 액션 툴바보다 작아지면
   THE 분할선 SHALL 툴바가 온전히 보이는 최소 위치에서 멈춘다.
6. THE 회귀 테스트 SHALL 760x480과 900x620에서 파일 액션 툴바·관리 액션 바·상태바의
   `winfo_rooty + winfo_height`가 창 클라이언트 높이를 넘지 않고 높이가 24px
   이상임을 검증한다.
7. THE 회귀 테스트 SHALL 디바이스·소스가 채워져 관리 트리가 커진 상태에서 검증한다
   (빈 상태에서는 트리가 공간을 다 가져가지 않아 결함이 드러나지 않는다).

## Requirement 2: 계정·설정 진입을 한 흐름으로 묶는다

사용자 스토리: 사용자로서, 로그인할 때 입력 창이 세 번 연달아 뜨고 중간에 취소하면
처음부터 다시 하는 일이 없기를 바란다.

### Acceptance Criteria

1. WHEN 사용자가 로그인을 실행하면 THE GUI SHALL 이메일·비밀번호·키 백업 암호를
   한 다이얼로그에서 입력받는다.
2. IF 로그인에 실패하면 THEN THE 다이얼로그 SHALL 닫히지 않고 입력값을 유지한 채
   실패 사유를 다이얼로그 안에 표시한다.
3. WHEN 새 설정을 만들면 THE GUI SHALL 폴더·서버 URL·디바이스 이름·키 생성 여부를
   한 창(단계 표시 포함)에서 입력받는다.
4. THE 상단 바 SHALL 로그인 상태에 따라 버튼 하나만 표시한다(비로그인: `로그인`,
   로그인: 계정 식별자 + `로그아웃`). 상시 비활성 버튼을 두지 않는다.
5. WHEN 로그인 상태이면 THE GUI SHALL 로그인한 계정(이메일)을 화면에 표시한다.

## Requirement 3: 파일 목록에서 백업 상태를 해석할 수 있다

사용자 스토리: 사용자로서, `대기 (1/3)` 같은 표기가 무엇을 뜻하는지 화면에서
알 수 있기를 바란다.

### Acceptance Criteria

1. THE 백업 컬럼 SHALL 상태를 색으로 구분한다(완료 success, 대기 accent,
   미백업 fg_subtle).
2. WHEN 복제본 수를 병기할 때 THE GUI SHALL `(온라인 복제본/필요 복제본)` 의미를
   툴팁으로 제공한다.
3. WHEN 목록이 비어 있으면 THE 파일 목록 영역 SHALL 사유별 안내 문구를 목록 한가운데
   표시한다(설정 없음 / 로그인 필요 / 폴더 비어 있음).
4. WHEN 사용자가 컬럼 헤딩을 클릭하면 THE 목록 SHALL 해당 컬럼으로 정렬하고 정렬
   방향을 헤딩에 표시한다.
5. THE 컬럼 헤딩 정렬 SHALL 데이터 정렬과 일치시킨다(이름 좌, 크기 우, 백업 좌).

## Requirement 4: 파일 조작에서 가상 경로를 직접 타이핑하지 않는다

사용자 스토리: 사용자로서, 이름을 바꾸려고 전체 경로를 손으로 입력하고 싶지 않다.

### Acceptance Criteria

1. THE 액션 SHALL `이름 변경`과 `이동`을 분리한다.
2. WHEN 사용자가 이름 변경을 실행하면 THE GUI SHALL 현재 이름만 편집하는 입력을
   제공하고, 경로는 현재 폴더로 고정한다.
3. WHEN 사용자가 이동 또는 복사를 실행하면 THE GUI SHALL 가상 폴더 선택 다이얼로그를
   제공한다(자유 텍스트 입력은 보조 수단으로만 남긴다).
4. IF 대상 경로에 같은 이름이 이미 있으면 THEN THE GUI SHALL 실행 전에 알리고
   덮어쓰지 않는다.

## Requirement 5: 동작의 의미를 화면에서 설명한다

사용자 스토리: 사용자로서, `복제 점검`이나 `복원`이 무엇을 하는 동작인지 눌러 보기
전에 알기를 바란다.

### Acceptance Criteria

1. THE 액션 툴바 버튼 SHALL 툴팁으로 동작 설명을 표시한다.
2. WHEN 버튼이 비활성이면 THE 툴팁 SHALL 활성 조건을 함께 표시한다(예: 파일을 하나
   이상 선택해야 함).
3. THE 툴팁 문구 SHALL 언어 전환을 따라간다.

## Requirement 6: 스토리지·디바이스 패널이 사람이 읽을 정보를 준다

사용자 스토리: 사용자로서, `loopback-2ce2ec`가 어느 파일인지, 얼마나 찼는지 한눈에
보기를 바란다.

### Acceptance Criteria

1. THE 소스 행 SHALL 소스 ID 대신 사람이 읽을 이름(종류 + 이미지 파일명)을 표시하고,
   전체 경로와 소스 ID는 툴팁으로 제공한다.
2. THE 용량 컬럼 SHALL 사용률 막대를 함께 표시한다.
3. WHEN 사용률이 90% 이상이면 THE 행 SHALL 경고 색으로 표시한다.
4. THE 관리 패널 SHALL 접기/펴기를 지원하고 마지막 상태를 `prefs`에 저장한다.

## Requirement 7: 피드백을 일관되게 준다

사용자 스토리: 사용자로서, 실패가 이어질 때 모달 팝업이 쌓이지 않기를 바란다.

### Acceptance Criteria

1. WHEN 작업이 실패하면 THE GUI SHALL 파괴적 확인이 필요한 경우를 제외하고 모달
   대신 상태 영역 인라인 배너로 알리고, 배너는 닫기 전까지 유지한다.
2. THE 인라인 배너 SHALL 같은 오류가 반복되면 새 배너를 쌓지 않고 발생 횟수를
   갱신한다.
3. WHEN 백업·복원·전송이 진행 중이면 THE 상태바 SHALL 진행률 막대를 표시한다.
4. THE 툴바 SHALL Accent(주 동작) 버튼을 하나만 둔다.
5. THE Accent 버튼 색 SHALL 디자인 시스템 CTA 색과 일치한다(현재 sv_ttk 기본 파랑이
   적용되어 `theme.PALETTE["success_emphasis"]`가 화면에 반영되지 않는다).
6. WHEN 창 닫기(X)로 트레이에 숨는 것이 처음이면 THE GUI SHALL 그 사실을 모달이 아닌
   1회 알림으로 안내한다(현재는 상태바 문구뿐이며, 그 상태바가 기본 창에서 보이지
   않는다).

## Requirement 8: 업로드는 파일 선택만으로 시작하고 진행은 목록에서 본다

사용자 스토리: 사용자로서, 업로드는 파일을 고르는 것으로 끝나고, 진행 상황은 별도
창이 아니라 지금 보고 있는 파일 목록에서 확인하기를 바란다.

현재 `UploadDialog`는 파일 목록·진행바·상태 로그·올리기/취소를 담은 별도 창이며,
그 창을 닫기 전까지 메인 창이 모달로 잠긴다.

### Acceptance Criteria

1. WHEN 사용자가 업로드를 실행하면 THE GUI SHALL 파일 선택 다이얼로그만 띄우고,
   선택이 끝나면 즉시 업로드를 시작한다.
2. THE GUI SHALL 업로드 전용 창을 두지 않는다(진행바·로그 창 없음).
3. WHEN 업로드가 진행 중이면 THE 파일 목록 SHALL 대상 파일을 행으로 표시하고 상태를
   `대기` → `업로드 중` → 완료 시 실제 파일 행으로 전환한다.
4. THE 업로드 대상 경로 SHALL 파일 선택 시점의 현재 폴더로 고정한다. 사용자가 다른
   폴더로 이동해도 업로드는 계속되며, 그 폴더의 목록에는 진행 행을 표시하지 않는다.
5. WHEN 자동 새로고침이 목록을 다시 그리면 THE GUI SHALL 진행 중인 업로드 행을
   유지한다.
6. IF 대상 경로에 같은 이름이 이미 있으면 THEN THE GUI SHALL 덮어쓰지 않고 그 행을
   `이미 있음`으로 표시한다.
7. IF 업로드가 실패하면 THEN THE 행 SHALL `실패`로 표시하고 다음 수동 새로고침까지
   남는다.
8. WHEN 여러 파일을 업로드하면 THE 상태바 SHALL `업로드 중 {i}/{n}: {name}`을
   표시한다.
9. THE 진행 중인 업로드 SHALL 목록 컨텍스트 메뉴에서 취소할 수 있다(진행 중인 파일은
   끝까지 두고 남은 파일만 건너뛴다).

## Requirement 9: 경로 이동은 브레드크럼과 `..` 행으로 한다

사용자 스토리: 사용자로서, 가상 경로를 손으로 입력하는 대신 파일 탐색기처럼 경로
조각을 눌러 이동하고, 목록 안의 `..`로 상위 폴더에 가기를 바란다.

현재 경로 바는 텍스트 입력 + `이동` 버튼이라 경로를 직접 타이핑해야 하고, 잘못
입력해도 그대로 조회를 시도한다.

### Acceptance Criteria

1. THE 경로 바 SHALL 현재 경로를 클릭 가능한 세그먼트로 표시한다(루트 + 각 폴더).
2. WHEN 사용자가 세그먼트를 클릭하면 THE GUI SHALL 그 경로로 이동한다.
3. THE 경로 바 SHALL 텍스트 입력 필드와 `이동` 버튼을 두지 않는다.
4. IF 경로가 길어 세그먼트가 경로 바 폭을 넘으면 THEN THE 경로 바 SHALL 앞쪽
   세그먼트를 `…` 하나로 접고, 클릭 시 접힌 경로를 메뉴로 제공한다.
5. WHEN 현재 폴더가 루트가 아니면 THE 파일 목록 SHALL 첫 행에 `..`를 표시한다.
6. WHEN 사용자가 `..` 행을 더블클릭하면 THE GUI SHALL 상위 폴더로 이동한다.
7. THE `..` 행 SHALL 크기·백업 값을 비우고, 어떤 파일 액션의 대상도 되지 않는다
   (선택해도 삭제·이동·백업 등이 활성되지 않는다).
8. WHEN 목록을 정렬하면 THE `..` 행 SHALL 정렬과 무관하게 항상 첫 행에 남는다.

## Requirement 10: 영어 UI 표기를 정돈한다

### Acceptance Criteria

1. THE 영어 컬럼 헤딩 SHALL 다른 라벨과 같은 대문자 규칙을 따른다(현재
   `name`/`size`/`backup`만 소문자).
2. THE 영어 문구 SHALL 영국 영어 철자를 유지한다.
3. WHEN 언어를 바꾸면 THE GUI SHALL 본문 위젯을 다시 만들되 현재 경로·선택·분할선
   위치를 유지한다.

## 범위 밖

- 파일 목록 가상 스크롤·썸네일
- 드래그앤드롭 업로드
- 새 화면 추가(설정 화면, 로그 뷰어)
- 업로드 바이트 단위 진행률. `actions.put_file`은 파일 단위 원자적 호출이고 데몬
  위임 경로(`/ctl/put`)도 동기 POST라 현재 구조에서는 알 수 없다. 데몬 put 핸들러에
  복제와 같은 진행 추적기를 붙이고 `/ctl/progress`를 확장하는 별도 작업이 필요하다.
